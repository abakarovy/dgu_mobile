# RuStore: категория, типы данных, POST_NOTIFICATIONS

Сводка по проекту `dgu_mobile` (портал college.dgu.ru, Firebase Messaging/Remote Config, без геолокации и без доступа к SMS/контактам по манифесту Android).

---

## Категория приложения

| Поле | Рекомендация |
|------|----------------|
| **Основная категория** | **Образование** — официальный клиент СПО/колледжа: расписание, успеваемость, сервисы студента, новости с портала. |
| **Дополнительная** (необязательно) | **Родителям** — в приложении есть сценарий для родителя (просмотр данных ребёнка в рамках доступа на портале). |

Если нужна альтернатива второй строки: **Новости и события** (акцент на ленту новостей колледжа) — обычно слабее, чем **Родителям**, если второй режим есть.

---

## Категории и типы данных (что отметить в форме)

Отмечайте всё, что приложение **собиравает с устройства** или получает после входа **с вашего сервера** и что уходит через **SDK/библиотеки** (в т.ч. Firebase).

### Местоположение

- **Приблизительное / точное** — по коду приложения разрешений геолокации нет; эти типы **обычно не указывать**.  
  *(Если на стороне портала хранится/обогащается IP — это может быть их политика; в форме приложения при отсутствии доступа к гео на клиенте чаще ничего не ставят.)*

### Личная информация

| Тип данных | Отмечать? | Комментарий для себя при заполнении |
|------------|-----------|-------------------------------------|
| **Имя** | ✅ | ФИО при регистрации/авторизации и в профиле. |
| **Адрес электронной почты** | ✅ | Вход, подтверждение OTP, связка аккаунта с порталом. |
| **ID пользователей** | ✅ | Идентификатор аккаунта, зачётная книжка, ID в системах колледжа. |
| **Адрес** | ❌ (если только не собираете) | В приложении не запрашивается почтовый/домашний адрес пользователя напрямую. |
| **Номер телефона** | ❌ или ✅ | Если на портале/в анкете телефон не обязателен и приложение его не отправляет — **не отмечать**. Если сбор есть — ✅. |
| **Раса, религия, политика, ориентация** | ❌ | Не собираются. |
| **Другие данные** | ✅ | Объективно: из профиля/1С могут показываться **дата рождения**, **курс, группа, отделение, статус** и другие учебные сведения — это попадает сюда, если интерфейс это отображает и данные синхронизируются с бэкендом. |

### Финансовые данные

- **Платёжные / покупки / кредит / прочее** — **не отмечать**, если приложение не принимает карты и не ведёт учёт покупок пользователя (контент стипендии/рейтинг — не «история покупок»).

### Здоровье и фитнес

- **Не отмечать** (нет медицинских/фитнес-сборов).

### Сообщения

- **SMS, e-mail содержание, им-клиент** — **не отмечать** (SMS не читаются; почта — не доступ к содержимому почтового ящика пользователя через приложение).
- **Другие сообщения в приложениях** — по желанию осторожно: текст **push** приходит через FCM. Часть магазинов трактуют только «чаты» и не включают сюда push от сервера. Если в вашей анкете RuStore явно ожидают push как «сообщение» и есть такой тип — можно согласовать с поддержкой RuStore; **минимальный безопасный вариант** — не включать без требования площадки.

### Фото и видео

| Тип | Отмечать? |
|-----|-----------|
| **Видео** | Только если пользователь действительно **загружает или записывает видео** в приложении (проверьте сценарии портфолио/файлов). Если нет — **нет**. |

*Фото с камеры/галереи через `image_picker` для портфолио часто трактуют как **Файлы и документы** или **Другой пользовательский контент** (ниже).*  

### Файлы и документы

| **Файлы и документы** | ✅ — выбор файлов (`file_picker`), загрузки материалов (например, портфолио). |

### Календарь и контакты

- **События календаря** — ❌ если нет синхронизации с календарём устройства.
- **Контакты** — ❌.

### Действия в приложении

| Тип | Отмечать? |
|-----|-----------|
| **Взаимодействие с приложением** | ✅ если бэкенд college.dgu.ru фиксирует обращения (экраны, действия после входа) — указать честно по факту вашей серверной политики. |
| **История поиска в приложении** | Только если есть **глобальный поиск** и запросы уходят на сервер как «поисковая история». Иначе **нет**. |
| **Установленные приложения** | ❌ |
| **Другой пользовательский контент** | ✅ биографии в портфолио, текстовые ответы, вложения — если пользователь их вводит. |
| **Другие действия** | По необходимости (редко нужно если выше всё покрыто). |

### Просмотр веб-страниц

- **История просмотра веб-страниц** — ❌ если контент открывается во **внешнем браузере** (`url_launcher`) без учёта истории внутри приложения. Если есть **встроенный браузер** с логированием URL на сервере — уточнить и возможно ✅.

### Данные о работе приложения

| Тип | Отмечать? |
|-----|-----------|
| **Отчёты об ошибках** | Если **Crashlytics/аналог явно не подключены** к приложению — обычно **нет**. Платформа RuStore/Google могут собирать сбои отдельно — см. их политику. |
| **Диагностика** | Можно **✅ минимально**: Firebase (Remote Config, инфраструктура Messaging) может относиться к технической телеметрии в зависимости от настроек проекта Firebase. При сомнениях составьте список с вашим firebase.com (Analytics включён ли). В `pubspec` нет `firebase_analytics` — явной аналитики в приложении нет. |
| **Другие данные о работе приложения** | Только если что-то ещё логируется на вашей стороне. |

### Идентификаторы

| **Идентификаторы** | ✅ — токен FCM для push; идентификаторы экземпляра/приложения в рамках Firebase; технические данные авторизации на сервер (сессионные ключи описываются в политике как приложение разработчика, не всегда дублируют эту строку — ориентируйтесь на подсказки формы RuStore). |

## Передача третьим лицам

В форме, где нужно указать получателей:

- **Google (Firebase)** — для **Firebase Cloud Messaging** и инфраструктуры Firebase (перечислите по требованиям RuStore/Google).
- **Сервер колледжа / оператор портала** — ваш бэкенд college.dgu.ru и связанная инфраструктура.

## Чувствительные разрешения: POST_NOTIFICATIONS

**Обоснование для модератора** (можно вставить целиком):

```text
Разрешение нужно только для показа push-уведомлений на Android 13+: новости колледжа, изменения расписания и информационные сообщения портала. Уведомления доставляет Firebase Cloud Messaging; без разрешения пользователь их не получит при отключённом системном показе.
```

Короче (если есть лимит поля):

```text
Push через FCM: новости, расписание и сервисные сообщения портала college.dgu.ru для пользователей, явно включивших уведомления.
```
